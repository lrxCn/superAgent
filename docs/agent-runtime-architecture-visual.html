Guardrails Router / Decision Memory Execution Trace / Hooks Fallback

1. 主生命周期

入口、上下文、路由、执行、输出、反思、记忆按阅读顺序排列。

2. Hooks / Guardrails / Trace

Hooks 不是业务流程节点，而是每个关键边界发出的生命周期事件。

3. ReAct 子流程

工具循环只在子图里回环。

4. Plan & Execute

先规划，再执行，再逐步验收。

5. Multi-Agent

中心编排，Worker 专业分工。

6. Reflection

只负责质量检查和有限轮修正。

State Contract

  • user_id / thread_id / run_id
  • messages / user_goal / intent
  • execution_mode / plan / current_step
  • tool_calls / observations
  • retrieved_memories / memory_candidates
  • agent_results / reflection_round
  • guardrail_results / trace_context
  • errors / budget / final_answer

Guardrail Boundaries

  • input_guard: 身份、权限、注入、敏感请求
  • route_guard: 模式选择前的策略判断
  • tool_guard: 工具权限、schema、高风险确认
  • output_guard: 脱敏、越权、格式、事实检查
  • memory_guard: 长期记忆写入前的价值与隐私检查

Trace Payload

  • run_id / thread_id / user_id
  • node_name / event_name / step_id
  • agent_name / tool_name / model_name
  • input_summary / output_summary
  • latency_ms / token_usage / cost
  • guardrail_decision / error_type / error_message
